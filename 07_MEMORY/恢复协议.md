# 断点恢复与上下文管理
1. status/verify。若有事务或锁异常先doctor，按README恢复，不覆盖异常现场。
2. status区分active_work与archived_work，已归档工作目录保留用于追溯，不能误认为未完成。
3. 读宪法、锁定事实、最新正式memory、当前卷纲、上一章全文及本章handoff。events/facts在历史各章存储，不能把最新章的数组当全部历史。
4. 填好/核对brief.json的entity_ids，运行context N。按context.md顺序读全部分页；分页是字符预算，不是token预算。核心事实不会被静默截断，但需要主动分批读取。
5. 对本章人物/道具/线索使用search，按next_offset继续结果；精确打开原文。检索只做中文子串，不是语义召回；名字、别称和ID都查一次，关系要追溯到双方事件。
6. 重新建立人物所在位置、知识来源、资源、时间、禁止披露项的引用清单。未知写未知；稿中已有但账本漏记的事实先核对，不补造历史。
7. 恢复包记录源文件指纹；重启/压缩后重新生成context，避免旧缓存误导。上下文来源变动也使preflight/check失效。
8. 每阶段写handoff：阶段、事实引用、未决问题、下一动作。没有可靠自动压缩回调保证，持续写入文件比临时总结更可靠。
